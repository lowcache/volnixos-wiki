# Product

## Platform

web

## Users

Two readers arrive, and the site makes no claim to serve one over the other:

- **The practitioner.** A NixOS user who found the repo and wants a working pattern to lift — the impermanence layout, the Lanzaboote setup, a microvm gateway definition. Usually arrives from a search engine directly onto an interior page, not the home page. Their job is scan, understand, copy, adapt.
- **The evaluator.** A peer, a hiring manager, or a link-follower sizing up whether this config is serious work. Lands on the home page and decides within seconds whether to keep reading.

Neither is courted at the other's expense. The site's own stated position is that the configuration is **opinionated and should be taken piecemeal, never installed whole** — this is a product fact, not marketing posture, and it constrains every claim the site is allowed to make.

## Product Purpose

Reference documentation for the `volnixos` NixOS configuration: a stateless, flake-driven workstation whose root filesystem is a `tmpfs` destroyed on every boot, with durable state mapped explicitly through `impermanence`. The wiki explains how each subsystem works and how it is wired, so a reader can understand a mechanism well enough to reimplement it in their own configuration.

Success is a reader leaving with a pattern they can apply — not a reader installing this configuration, and visiting the blog for an indepth look at how a setting got there.

## Positioning

The whole machine is described by text, and nothing survives a reboot that was not explicitly named. That is the mechanism the site exists to make legible. It is not a distribution, not a starter template, and not a dotfiles dump: it is a single specific machine documented as proof-of-work.

Sibling to the **Volatile Testimony** blog (`volnixos-blog`, same domain root, `infernalcode.com`), which is the experiential/narrative account of the same configuration. The wiki is the reference tier; the blog is the testimony tier. They are separate entities that share a subject.

## Operating Context

- Read at a terminal, usually alongside the reader's own `configuration.nix` in another window.
- Search-first for practitioners: Pagefind full-text search is the primary entry path for interior pages.
- Content is organized in seven sections: Architecture, Networking, System, Phone, Desktop, Reference, Tooling.
- The target host `volnix` is one specific machine: AMD Ryzen laptop, hybrid AMD iGPU + NVIDIA RTX 4050, ASUS chassis. Hardware-specific advice is not portable and the site must not imply otherwise.

## Capabilities and Constraints

- Hugo 0.164.0 static site. The **E25DX** theme is consumed as a Hugo Module (`github.com/dumindu/E25DX`, pinned by commit in `go.mod`), not a submodule — `go` must be on PATH to build. Theme config is deliberately ignored (`ignoreConfig = true`); everything the theme needs is declared in `hugo.toml`.
- Deployed to Cloudflare Workers. `git push` triggers Workers Builds running `./build.sh`; `make deploy` is the local rescue path.
- Search is a **post-build** step: Hugo renders the UI, `pagefind --site public` produces the index.
- `check-link.sh` fails the build on broken internal links.
- No taxonomies (`disableKinds = ["taxonomy", "term"]`).
- Left sidebar navigation is generated by walking the content tree (project override of the theme partial), so a page cannot exist without appearing in the nav.

### Must be preserved by any redesign

Page content, URL structure, section navigation, and Pagefind search. Everything else — home page markup, banner/logo assets, the legacy `vol-*` MkDocs HTML, the entire CSS layer — is replaceable.

## Brand Commitments

- Name: **Volatile NixOS Configuration**. Author: `lowcache`.
- Kin to the Testimony blog through structure and cross-links, **not** through shared palette. The wiki gets its own visual world; the blog's rust/gold editorial identity is not inherited.
- Voice is plain, technical, and unembellished. The configuration is presented as proof-of-work, never as a product.

## Evidence on Hand

- Real content: 24 pages of first-hand documentation across seven sections, all written against a configuration that actually runs.
- Real source repository: `github.com/lowcache/volnixos`.
- `static/assets/{logo,banner,favicon}.png` — carried over from the MkDocs build; replaceable.
- **No** benchmarks, user counts, testimonials, install statistics, or third-party endorsements exist. None may be invented or implied.
- Support ask: an existing Buy Me a Coffee link. This is the only monetization currently live.

## Product Principles

1. **Piecemeal, not wholesale.** Every page serves a reader borrowing one mechanism. Nothing may imply this config should be adopted entire.
2. **The text is the machine.** Configuration source is the primary evidence; show it rather than describing it.
3. **Explicit or gone.** Persistence, secrets, and state are opt-in by name — the site's own information architecture should feel the same way.
4. **Reference tier, not testimony tier.** Narrative and experience belong to the sibling blog. Here, answer the question.
5. **No invented authority.** No metrics, adoption claims, or endorsements. The work is the argument.

## Accessibility & Inclusion

- All motion must be gated behind `prefers-reduced-motion`; nothing may carry meaning that exists only while moving.
- The site is read primarily as long-form technical prose with dense code blocks — body legibility and code contrast outrank expression on interior pages.

## Monetization — open decision

Google Analytics is approved to wire. Display advertising (AdSense) is **undecided**: the concern is credibility bleed onto the sibling blog. Resolution recorded in `DESIGN.md`: the layout reserves a support rail that always carries real author content (repository link, support ask, related pages), so ad inventory can be introduced later without reflow and without sitting adjacent to tool recommendations. No ad code ships until the user decides.
